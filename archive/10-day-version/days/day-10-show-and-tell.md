## Presentation Tips

### 1. Start with the Problem

**❌ Don't start with:**
"I created a design spec template..."

**✅ Start with:**
"Creating design specs used to take me 2 hours and they were inconsistent. Now it takes 15 minutes and they're always complete..."

**Hook your audience with the problem they might have too!**

### 2. Show, Don't Just Tell

**Live demo is powerful:**
- Open terminal
- Show the command
- Walk through output
- Point out key parts

**Even better:**
- Before/after comparison
- Side-by-side of old way vs. new way

### 3. Be Honest About Challenges

**Share what didn't work:**
- "First version of my command was too generic"
- "I initially organized files wrong"
- "Took 3 tries to get the template right"

**People learn more from failures than successes!**

### 4. Give Actionable Tips

**❌ Vague:**
"Use templates"

**✅ Specific:**
"Start with a simple template, test it on 2-3 projects, then refine. Keep templates in ~/Documents/templates/ so you can find them easily."

### 5. Stay on Time

**Practice beforehand:**
- Aim for 7 minutes
- Leaves time for questions
- Respects everyone's time

**If you go over:**
- Skip less important details
- Offer to share more offline

## Example Presentations

### Example 1: Research Synthesis Workflow

```markdown
## From 3 Hours to 30 Minutes: User Research Synthesis

### The Problem
After conducting 5-8 user interviews, I'd spend 3-4 hours:
- Reading through all transcripts
- Manually noting themes
- Copy-pasting quotes into docs
- Creating tables and summaries

### My Solution
Created a structured workflow with Claude Code:
1. Organize interviews in /interviews/ folder
2. Custom command: /research-synthesis
3. Claude Code reads all files, identifies themes
4. Generates synthesis doc with quotes and frequencies
5. I review and add strategic insights

### Demo
[Shows folder structure]
[Runs /research-synthesis command]
[Walks through generated synthesis document]

### Impact
- Time: 3 hours → 30 minutes (6x faster!)
- Consistency: Every synthesis has same structure
- Thoroughness: Claude Code catches themes I might miss
- Focus: I spend time on insights, not formatting

### Tips for You
1. Start with good organization (one file per interview)
2. Include participant number in filename
3. Let Claude Code find patterns, you provide interpretation
4. Review output - AI assists, you decide
```

### Example 2: Custom Command System

```markdown
## My 5-Command Productivity System

### Before Claude Code
- Inconsistent documentation
- Started each doc from scratch
- Forgot important sections
- Spent time on formatting

### My 5 Commands
1. /design-spec - Complete design specification
2. /competitive-analysis - Competitive analysis setup
3. /meeting-notes - Format meeting notes
4. /status-update - Weekly status update
5. /component-doc - Design system component docs

### Demo
[Shows ~/.claude/commands folder]
[Picks 2 commands to demo live]
[Shows before/after of using command]

### My Typical Week
Monday: Use /meeting-notes after team sync
Tuesday-Thursday: Use /design-spec as needed
Friday: Use /status-update for week recap
Ongoing: /competitive-analysis for market research

### Results
- Save 2-3 hours per week
- All docs have consistent format
- Never forget important sections
- Team can use same commands

### How to Get Started
1. Identify your 3 most repetitive tasks
2. Create command for each (start simple!)
3. Test for a week
4. Refine based on what you learn
5. Share with team
```

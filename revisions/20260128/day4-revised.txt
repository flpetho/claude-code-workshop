## Part 1: How Professionals Use Claude Code (20 min)

### The Context Principle

**Simple truth:** More context = Better output

**What you've been doing:**
```
Create project → Run Claude Code → Build features
```

**This works!** But there's a more powerful approach...

---

### The Two-Phase Workflow

**What professionals discovered:**

Using TWO AI agents in sequence produces 10x better results:

**Phase 1: PLANNING** (Any AI agent)
- Claude Desktop
- ChatGPT
- Gemini  
- Any AI assistant

**Use planning agent to:**
- Define requirements clearly
- Make technical decisions
- Design architecture
- Create documentation
- Break down tasks

**Phase 2: BUILDING** (Claude Code)
- Reads planning documents
- Builds according to specs
- Implements features
- Follows architecture

---

### Why This Works: Real Example

**Project:** Meeting notes analyzer

#### Approach A: Direct Building (What you've been doing)

```
You: "Build a meeting notes analyzer"
Claude Code: "Sure! What fields should it have?"
You: "Um... title, date, notes..."
Claude Code: "Should it extract action items?"
You: "Oh yes, add that"
Claude Code: "What format for action items?"
You: "Hmm, not sure... make it a list?"
[Lots of back and forth, revisions, uncertainty]
```

**Time:** 2 hours of iteration
**Result:** Works, but could be better

#### Approach B: Planning First (Professional workflow)

**Step 1: Planning Phase (30 min)**

You tell planning agent (Claude Desktop):
```
"Help me plan a meeting notes analyzer. Ask me questions 
about requirements, users, features, and technical approach."
```

Planning agent creates:
- OVERVIEW.md (what it does, who uses it)
- USER-STORIES.md (use cases)
- ARCHITECTURE.md (how it should work)
- TECHNICAL-STACK.md (technologies to use)
- TASKS.md (implementation steps)

**Step 2: Building Phase (45 min)**

You tell Claude Code:
```
"Read all files in .planning/ folder. Build the meeting 
analyzer according to these specifications."
```

Claude Code:
- Reads all planning docs
- Understands complete context
- Builds exactly to spec
- Few questions, works first time

**Total Time:** 75 minutes (vs 120 min direct)
**Result:** Higher quality, fewer revisions

---

### The Magic Ingredient: CONTEXT

**Minimal context:**
```
"Build a tool"
```

**Some context (what you're doing now):**
```
# CLAUDE.md
Project: Meeting Analyzer
Users: Product managers
Features: Extract action items
Tech: HTML/JS
```

**Maximum context (professional approach):**
```
.planning/
  ├── OVERVIEW.md (what and why)
  ├── USER-STORIES.md (who and how)
  ├── ARCHITECTURE.md (technical design)
  ├── TECHNICAL-STACK.md (technology choices)
  ├── TASKS.md (step-by-step breakdown)
  └── HANDOFF.md (ready to build summary)
```

**Result:** Claude Code has complete picture before writing any code.

### When to Use This Approach

**Use two-phase workflow for:**
- ✅ Complex projects (multiple features)
- ✅ When quality really matters
- ✅ When you're unsure of best approach
- ✅ Team projects (planning docs help collaboration)

**Simple direct approach is fine for:**
- ✅ Quick prototypes
- ✅ Learning exercises
- ✅ Simple one-feature tools
- ✅ Experimenting

**Both approaches are valid!** Choose based on project needs.

## Part 2: Polish Your Project (25 min working session)

### What "Polish" Means

**Before polish:**
- ✅ Works functionally
- ❌ Basic styling
- ❌ No error handling
- ❌ Unclear instructions
- ❌ Incomplete README

**After polish:**
- ✅ Works great
- ✅ Professional styling
- ✅ Helpful error messages
- ✅ Clear user guidance
- ✅ Complete documentation

---

### Polishing Checklist

Work through these in order:

#### 1. User Experience (10 min)

**Ask Claude Code:**

```
"Review my project for UX improvements:
- Are instructions clear?
- Are labels descriptive?
- Are error messages helpful?
- Are success states obvious?
- Is loading indicated?
- Are empty states handled?

Fix any issues you find."
```

**Test yourself:**
- Pretend you've never seen this before
- Can you figure out what to do?
- Are buttons clearly labeled?
- Do you know what happened after clicking?

#### 2. Visual Design (8 min)

```
"Improve visual design:
- Consistent spacing (use 8px grid system)
- Typography hierarchy (clear headers, readable body text)
- FamilySearch brand colors used correctly
- Button states (hover, active, disabled)
- Professional shadows and borders
- Mobile responsive (test on small screen)"
```

#### 3. Error Handling (7 min)

```
"Add error handling:
- What if data file is empty?
- What if form fields are invalid?
- What if network request fails?
- Show helpful error messages
- Provide recovery options
- Don't just console.log errors"
```

**Test edge cases:**
- Submit empty form - what happens?
- Try invalid data - clear error?
- Break something intentionally - recoverable?

**More planning = Better building**

**90% functional + 10% polish = Professional result**

That 10% is:
- Error messages
- Loading states

- Visual consistency
- Documentation
